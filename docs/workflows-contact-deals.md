# Потоки: проверить другие сделки контакта

1. Событие запуска: «amoCRM: добавлена сделка».
2. В разделе «Запросы → Сделки» добавьте «Сделки контакта».
   - Контакт: «Основной контакт сделки».
   - ID исходной сделки: `{{lead.id}}`.
   - Исключить сделку: `{{lead.id}}`, если новая сделка не должна считаться совпадением.
   - Если нужен конкретный контакт, выберите «Указать ID контакта» и подставьте его ID.
3. «Действия → Управление потоком → Фильтр списка».
   - Список: `{{ $json.items }}`.
   - Совпадение: «Все условия · И».
   - Поле `pipeline_id`, сравнение «Равно», значение — ID нужной воронки.
   - Поле `status_id`, сравнение «Равно», значение — ID нужного этапа.
   - Для проверки только воронки или только этапа оставьте одно правило. Значения правил могут быть переменными.
4. «Условие»: `{{ $json.count }}` → «Больше» → `0`.
   - «Да»: есть другая подходящая сделка.
   - «Нет»: подходящих сделок нет.

Фильтр проверяет каждый элемент списка и возвращает `items`, `count`, `has_matches`, `input_count`. Это обработка массива внутри одной ноды, не цикл с повторным исполнением последующих действий для каждой сделки.

Запрос сначала получает связи контакта, затем полные сделки пакетами до 250 ID. Пустой контакт не превращается в запрос всех сделок аккаунта. Более 5000 связанных сделок или неожиданная неполная страница завершают ноду ошибкой, а не ложным результатом «совпадений нет». Доступность сделок ограничена правами подключения amoCRM.

Основание API: [контакт с `with=leads`](https://www.amocrm.ru/developers/content/crm_platform/contacts-api), [получение сделок](https://www.amocrm.ru/developers/content/crm_platform/leads-api).

## Полотно

- Shift + протянуть рамку по пустому месту: выделить несколько нод.
- Shift + клик по карточке: добавить или убрать её из выделения.
- Перетащить выделенную карточку: перенести группу, сохранив взаимные расстояния.
- Escape: снять выделение.
- Вставка через «+» сохраняет связь «источник → новая нода → прежняя цель», размещает новую ноду рядом и освобождает место сдвигом следующих нод. Несвязанные ноды не переставляются. Для вставленного условия прежнее продолжение подключается к «Да»; «Нет» остаётся свободным.

## HTTP-запрос

Находится в «Действия → Управление потоком». Поля: метод, URL, заголовки JSON, тело JSON, таймаут 1–30 секунд. Ответ следующего шага: `{{ $json.status }}`, `{{ $json.body }}`.

Внутри JSON выражение пишется строкой, например `{"lead_id":"{{lead.id}}","items":"{{ $json.items }}"}`. Ссылки `$json`/`$node` сохраняют типы значений; старые маски вроде `{{lead.id}}` возвращают текст.

Тестовый режим не отправляет HTTP-запрос. Реальное выполнение допускает только публичные HTTP(S) адреса, без переходов по редиректам и доступа во внутреннюю сеть. DNS-адрес закрепляется на время запроса, ответ ограничен 1 МБ. HTTP 3xx/4xx/5xx дают ошибку ноды; автоматических повторов нет.

## Проверка изменений

Реализация и автоматические проверки выполнены локально. Ручная браузерная проверка новых функций не завершена: автопроверка безопасности заблокировала открытие пустого тестового сценария; запрошено разрешение пользователя. Эти изменения пока не выложены на production.
