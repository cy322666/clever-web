# Массовое действие

Архив виджета версии 1.0.46 добавляет запуск из меню «ещё» в списках сделок,
контактов и компаний amoCRM (`llist-0` и `clist-0`).

В редакторе потока нужно добавить способ запуска **Массовое действие** и включить
поток. В списке amoCRM отметить сущности, открыть «ещё», выбрать «Потоки» и нужный
поток. В этом меню отображаются только включённые потоки текущего владельца
с основным или дополнительным стартом `amo-bulk`.

Для каждой выбранной сущности создаётся отдельный запуск каждой ветки
`amo-bulk`. Ручные, кнопочные и DP-ветки при этом не запускаются. За одно действие
принимается от 1 до 250 элементов. Повторные пары `(type, id)` удаляются; контакт
и компания с одинаковым числовым ID остаются разными сущностями.

На входе доступен ID выбранной сущности:

- `item.id` и `entity_id`: ID текущего элемента;
- `entity`: `lead`, `contact` или `company`;
- `lead.id`, `contact.id` или `company.id`: только соответствующий тип;
- `payload.lead_id`, `payload.contact_id` или `payload.company_id`;
- `source`: `amocrm-list-bulk`, `event`: `amo-bulk`.

Полная карточка автоматически не загружается. Для полей сущности добавляется
следующая нода получения сделки, контакта или компании по ID.

Новый клиент запрашивает список с `source=amo-bulk` и передаёт на `/bulk-run`
`entities: [{type: "contact", id: 42}]` и тот же `source`.
Старый формат `lead_ids` поддерживается: без `source` используется ручной старт,
с `source=amo-button` используется кнопочный старт. Существующие потоки
автоматически не конвертируются.

## Выпуск

Нужны обе части: серверные изменения и обновлённый архив в интеграции amoCRM.
Одна замена ZIP на сервере не обновляет уже установленный в amoCRM виджет.
Сначала публикуется серверная часть, затем пакет. Миграции БД не нужны.

Сборка из `application/`: `node scripts/build-workflow-widget.mjs`.
Обновляются `public/amocrm/workflows/widget.zip` и `clever-workflow-buttons.zip`.

Проверки: `WorkflowBulkActionTest`, `WorkflowDigitalPipelineTest`,
`WorkflowConnectionAccessTest`, `workflow-widget-bulk.test.mjs`.
Локальные тесты используют SQLite, подменённую очередь и SDK без обращений к CRM.
Они не заменяют проверку установленного архива в настоящем аккаунте amoCRM.
