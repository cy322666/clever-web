# Контроль ответов

Виджет контроля времени ответа клиентам в amoCRM. Внутренний ключ и существующие адреса сохраняют имя `finder`.

## Возможности

- Отслеживание входящих сообщений и ответов менеджера или Salesbot.
- Интервал в часах и минутах, до 100 повторных проверок.
- Рабочие дни, несколько интервалов, часовой пояс, ночные смены и пересечения расписаний.
- Запуск своего активного сценария «Потоков» и/или задача в amoCRM.
- Ответственный за задачу: выбранный сотрудник или пункт «Текущий ответственный». Во втором случае ответственный запрашивается у сделки беседы в момент создания задачи; если сделки нет, у контакта.
- Текст задачи передаётся точно из настроек, без служебных дописок. Номер попытки остаётся в истории виджета.
- Отдельный сценарий после ответа, если действие по просрочке уже было запущено.
- История попыток, результатов, отмен и ошибок.

## Поведение

Первое неотвеченное входящее сообщение запускает таймер. Следующие входящие сообщения его не обнуляют. Ответ в том же чате останавливает повторы; следующее сообщение клиента начинает новый цикл. События с одинаковой секундной меткой считаются отвеченными, если есть исходящее сообщение с этой меткой.

Вне расписания время ожидания не увеличивается, действия по просрочке не выполняются. Проверка запускается раз в минуту, поэтому возможна задержка до минуты плюс время обработки очереди. После простоя выполняется одна проверка, затем отсчитывается следующий интервал, без массового воспроизведения пропущенных повторов. Уже рассчитанный ближайший срок сохраняется при редактировании параметров; новые параметры применяются к следующим срокам и новым циклам.

Задача создаётся в текущей сделке беседы, при отсутствии сделки в контакте. Текст сообщения не сохраняется. Хранятся идентификаторы и время событий. Счётчик `finder.attempt` начинается с 1; он передаётся в сценарий вместе с `finder.cycle`, `finder.chat_id`, `finder.talk_id`, `finder.pending_since`, `finder.replied_at`, `lead`, `contact` и `account`. Сценарий запускается через основной вход `trigger`, требуется действующий доступ к «Потокам».

Пришедший ответ отменяет ещё не начатые действия по просрочке. Если все действия успели отмениться, сценарий ответа не запускается. Начатое внешнее действие уже может завершиться после ответа. Ошибки POST и прерванные попытки автоматически не повторяются: сначала нужно сверить результат в amoCRM. Статус «Выполнено / запущено» означает созданную задачу либо постановку сценария в очередь; результат самого сценария находится в истории «Потоков».

## Подключение

1. Применить миграцию `2026_09_24_130000_create_finder_tables.php` обычным процессом развёртывания.
2. Проверить работу Laravel scheduler и очереди «Потоков». Команда `finder:check` уже добавлена в расписание каждую минуту.
3. В магазине платформы открыть «Контроль ответов». Настройки создаются стандартным механизмом каталога. После установки используется подключение, выбранное для виджета. Для старых настроек сохраняется резервный выбор общей авторизации платформы.
4. Выбрать действия и сохранить. Кнопка amoCRM в шапке показывает домен текущего аккаунта и открывает авторизацию интеграции «Контроль ответов» с `AMO_FINDER_CLIENT_ID`. Секрет используется только сервером при обмене кода установки. Рядом находится отдельная кнопка обновления сотрудников и типов задач.
5. После подключения amoCRM подписка на сообщения создаётся автоматически отдельной задачей очереди. Перед записью проверяется существующая подписка, а после записи выполняется повторный GET: должны присутствовать оба события `add_message` и `add_outgoing_message`. При временной ошибке API задача повторяется без повторного обмена OAuth-кода и без дублирования уже установленного хука. Затем можно нажать «Включить». Единственная кнопка «Включить / Выключить» управляет и виджетом, и отслеживанием. Включение проверяет настройки и доступ, выключение отменяет ожидающие проверки. Сохранение формы само по себе не включает виджет.
6. Проверить на отдельном тестовом диалоге входящее сообщение, просрочку, задачу/сценарий и ответ. Реальные сообщения и сценарии в рамках разработки не запускались.

Вебхук: `POST /api/finder/hook/{setting}/{signature}`. Подпись привязана к настройке, владельцу и подключению. Другие вебхуки аккаунта не изменяются. Публичный HTTPS адрес берётся из существующей настройки `workflow-webhooks.public_url`, иначе из `app.url`.

Нужны тариф amoCRM с доступом к вебхукам и канал, который передаёт сообщения в amoCRM. Виджет начинает наблюдение с полученных событий; историю прошлой переписки не импортирует. Отдельный архив для amoМаркет не входит в эту реализацию платформы. Форма использует стандартную сетку виджетов: настройки слева, общий компонент тарифов справа. В тарифах указаны цены за аккаунт до 5 пользователей включительно: 1 000 руб за месяц, 6 000 руб за полгода, 10 000 руб за год. При количестве пользователей больше 5 цена составляет 249 руб за каждого пользователя аккаунта в месяц. Условия доступа проверяются общим механизмом подписок платформы.

## Установка и отключение в amoCRM

- Redirect URL установки: `https://app.clevercrm.pro/api/amocrm/install/finder`.
- Хук отключения: `https://app.clevercrm.pro/api/amocrm/off/finder`.

Оба адреса принимают GET и POST через общие обработчики платформы. Установка требует `code` и `referer` и ставит зашифрованный код в очередь. POST и JSON-запросы получают HTTP 202, без обязательных параметров 422. Браузерный GET перенаправляется на страницу проверки подключения без кода авторизации в адресе. Она ждёт результат очереди и открывает настройки только для вошедшего владельца аккаунта. Для гостя или другого пользователя показывается предложение войти обычным способом; автоматического входа нет. Ошибка и истечение срока ожидания отображаются отдельно от успешного подключения.

После создания интеграции в amoCRM нужно настроить `AMO_FINDER_CLIENT_ID` и `AMO_FINDER_CLIENT_SECRET`; `AMO_FINDER_REDIRECT_URI` по умолчанию равен адресу установки. Код отдельной интеграции обменивается только с её ключами, без подстановки ключей общей интеграции платформы. Статус браузерной установки хранится в общем database cache 30 минут. Ошибка отправки письма после сохранения OAuth-токенов не отменяет завершённое подключение и записывается отдельно.

При подключении из настроек зашифрованный state со сроком 30 минут сохраняет исходного владельца и настройку. Установка не создаёт новый кабинет по другому email из amoCRM. Уже принадлежащее другому владельцу подключение автоматически не переносится. Подключение открывается в той же вкладке, после завершения владелец возвращается к обновлённым настройкам. Установка из amoМаркет без state использует обычный поиск владельца аккаунта. Хук отключения, как у «Потоков» и импорта Excel, записывает событие и отправляет стандартное уведомление, возвращает HTTP 200. Он не отключает общее подключение amoCRM и не выключает мониторинг на платформе. Для остановки мониторинга используется кнопка «Выключить» в Finder.

## Проверки

`cd application && vendor/bin/phpunit tests/Unit/Finder tests/Feature/Finder`

Тесты используют SQLite в памяти, подменённый API amoCRM и очередь. Они проверяют расписание, повторные события, порядок доставки, остановку и лимиты, разделение аккаунтов, задачи, передачу контекста в «Потоки», сохранение формы и регистрацию вебхуков с проверкой ответа. Миграция проверена на SQLite. Нагрузку и конкуренцию на PostgreSQL, доставку реальных вебхуков и выполнение в production нужно проверить после развёртывания.

Официальные форматы: [вебхуки сообщений](https://www.amocrm.ru/developers/content/crm_platform/webhooks-format), [подписка на события](https://www.amocrm.ru/developers/content/crm_platform/webhooks-api), [привязка беседы к сущности](https://www.amocrm.ru/developers/content/crm_platform/talks-api).
